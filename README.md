# ВышКат

Консольное приложение для учёта транспорта и вещей в сервисе проката. Написано на C# и .NET 6. Данные хранятся в памяти, поэтому после закрытия программы список имущества очищается.

## Как запустить

Нужен .NET SDK 6. При первой сборке пакеты скачиваются из NuGet.

```powershell
dotnet build VyshCat.sln
dotnet run --project VyshCat
```

В меню можно добавить транспорт или вещь, посмотреть количество имущества и расход энергии, вывести транспорт для новичков или весь список с инвентарными номерами.

Для запуска готового примера:

```powershell
dotnet run --project VyshCat -- --demo
```

В примере добавляются велосипеды, самокаты, шлем и зарядный шкаф. Один неисправный самокат не проходит техосмотр. В итоге в парке остаются 3 транспортных средства и 2 вещи. Общий расход — 6,5 кВт*ч в сутки, для новичков подходят 2 транспортных средства.

## Как устроен проект

В папке [Models](VyshCat/Models) находятся классы имущества. Общий класс `InventoryItem` хранит номер и название. От него наследуются `Vehicle` для транспорта и `Equipment` для вещей. Дальше идут конкретные классы: велосипед, электровелосипед, электросамокат, шлем и зарядный шкаф.

Интерфейс `IInventoryItem` нужен для общего списка имущества. `IEnergyConsumer` используется при подсчёте энергии: его реализуют электрический транспорт и зарядный шкаф. У обычного велосипеда и шлема расхода энергии нет.

[FleetService](VyshCat/Services/FleetService.cs) хранит список имущества, добавляет объекты и собирает данные для отчётов. Перед добавлением транспорта он обращается к [ServiceCenter](VyshCat/Services/ServiceCenter.cs). Сейчас техосмотр проверяет только `IsOperational`: исправный транспорт принимается, неисправный — нет. Более подробная диагностика в задании не описана. Вещи добавляются без техосмотра.

Для новичков выбирается принятый транспорт с оценкой простоты от 6 до 10. Инвентарные номера уникальны с точностью до регистра, пустые номера и названия, отрицательный расход, оценки вне диапазона 1–10 не допускаются.

[ConsoleMenu](VyshCat/ConsoleMenu.cs) читает ввод и показывает результаты. В [Program.cs](VyshCat/Program.cs) настраивается DI-контейнер и запускается меню.

## SOLID

- **SRP:** у каждого класса своя задача. Модели хранят и проверяют данные, `ServiceCenter` отвечает за техосмотр, `FleetService` — за учёт, `ConsoleMenu` — за общение с пользователем.
- **OCP:** новый вид транспорта можно унаследовать от `Vehicle`. Существующие методы учёта будут с ним работать. Если он потребляет энергию, нужно реализовать `IEnergyConsumer`. Достаточно добавить класс и пункт меню, отчёты менять не нужно.
- **LSP:** вместо `Vehicle` можно передать велосипед или самокат. Они соблюдают общие правила транспорта и работают с теми же методами приёмки и учёта.
- **ISP:** для инвентаризации и расхода энергии сделаны разные интерфейсы. Поэтому шлему не нужно добавлять свойство расхода, которое ему не подходит.
- **DIP:** Этот принцип здесь выражен наиболее явно. `FleetService` получает `IServiceCenter` через конструктор и не создаёт техосмотр сам. Конкретная реализация задаётся в DI-контейнере.

Есть нарушение OCP: при добавлении нового вида транспорта придётся дописать пункт в `ConsoleMenu` — для простоты меню. Хранение имущества и расчёт отчётов в одном сервисе, т.к. логики пока немного.

## Тесты

Запуск тестов с измерением покрытия:

```powershell
dotnet test VyshCat.sln --collect:"XPlat Code Coverage"
```

В [FleetServiceTests](VyshCat.Tests/FleetServiceTests.cs) проверяются основные правила учёта:

- `InspectionResult` — принятие и отказ по решению техосмотра. Через DI-контейнер передаётся [FakeServiceCenter](VyshCat.Tests/FakeServiceCenter.cs), который возвращает заданный результат: `true` или `false`.
- `BeginnerVehicles` — граница для новичков: оценка 5 не подходит, а 6 уже подходит.
- `TotalEnergy` — общий расход энергии и количество транспорта и вещей.
- `DuplicateNumber` — запрет повторного инвентарного номера.

[ServiceCenterTests](VyshCat.Tests/ServiceCenterTests.cs) проверяет техосмотр исправного и неисправного транспорта. [ConsoleMenuTests](VyshCat.Tests/ConsoleMenuTests.cs) проверяет добавление имущества через меню, отказ в приёмке и вывод отчёта и списка имущества.
